# シェルスクリプトの書き方についての備忘録
[Unix&Linuxコマンド・シェルスクリプトリファレンス](https://shellscript.sunone.me/tutorial.html)
## シェルスクリプトとは?

複数のコマンドと条件分岐やループ処理等を使用し、一連の処理を実現するプログラムのことである。bash、zsh などのシェルを利用し、シェルによって解釈・実行されるスクリプトなので、シェルスクリプトと呼ばれる。

**「シェルスクリプト」**$\not ={「シェル」}$

## シェルスクリプトを作成する

古いUnix環境ではshやkshが使用されていたが、最近のLinuxではbashやzshなどが一般的

```bash
#!/bin/bash

echo "Hello World!"
exit 0
```
先頭に指定した`#!`で始まる「シバン」と呼ばれる文字列は、スクリプトを実行するためのインタプリタを指定している。(ここではbash)
必ず1行目で指定する。

## シェルスクリプトの実行
---
シェルスクリプトを実行する方法は大きくわけて2つ

1. bashコマンドに実行するシェルスクリプトのファイルを指定する。 `$ bash helloworld.sh`
2. シェルスクリプトのファイルをコマンドとして直接実行する `$./helloworld.sh`

### bashコマンドでの実行
---

```bash
$bash helloworld.sh
Hello World!
```

これは、**カレントディレクトリにファイルがある場合のみに適用される**

#### 実行権限

シェルスクリプトをコマンドとして直接実行するためには、主に以下の2つの条件が必要
1. ファイルのパーミッションに実行権が付与されていること
2. シェルがファイルの場所を特定できること

```bash
$ ls -l helloworld.sh
-rw-rw-r-- 1 sunone sunone 43  5月  7 15:23 helloworld.sh
```
ls -lの結果の一番左から2~4番目が自分の持っている権限(ファイル所有者の権限)を表している.`rw-`なため、「読み込み権限(`r`)」と「書き込み権限(`w`)」があることになる。

実行権限にあたる`x`がないため、chmodコマンドでこれを付与する。

```bash
$ chmod +x helloworld.sh
$ ls -l helloworld.sh
-rwxrwxr-x 1 vagrant vagrant 43  5月  7 15:23 helloworld.sh
```

実行権を意味する`x`が表示されていれば正常に実行権が付与されたことになる。

#### シェルがファイルを特定できる場所

1. 絶対パス指定でコマンドを実行 `/home/sunone/helloworld.sh`
2. 相対パス指定でコマンドを実行 `./helloworld.sh`
3. PATHの通ったディレクトリにファイルを置いてコマンドを実行 `$ helloworld.sh`

の3つのいずれかで可能。

`ls`や`echo`がコマンド名だけで実行できるのは,**環境変数PATH**にこれらコマンドが存在する`/bin`が設定されているため。

```bash
$ echo $PATH
/usr/local/bin:/usr/bin:/usr/local/sbin:/usr/sbin:/usr/local/bin:/usr/bin
```

### シェルスクリプトのパスへの登録

```bash
$ export PATH = "${PATH}:."
```
PATHはコロン区切りで設定するため、現在のPATHの設定値`${PATH}`にコロンを付与し、、カレントディレクトリを追加したものを環境変数PATHに設定する。(前方に設定したディレクトリほど優先度が高い、つまり同じコマンドがあれば前方のディレクトリが優先)

さらに`export`で現在ログイン中のシェルと、そこから派生したシェルで、指定した変数(PATH)の値を有効にすることができる。

```bash
$ helloworld.sh
Hello World!
```

## シェルスクリプトの文法

シェルスクリプトを文法ではなく、長いコマンドラインと捉える。他の言語とは異なり、**ifやforといった制御文もコマンドであり、それらを含めてすべてコマンドの羅列にすぎない。**シェルスクリプトの場合は、**syntax errorをcommand errorとして考えるとわかりやすい。**
例えば、シェル変数を設定する場合、シェルスクリプトでは`=`の前後にスペースがあるとエラーになる。
```bash
$ var = "hoge"
bash: var: コマンドが見つかりません
```

これは、シェルが変数varを「スペースが有ることによって`var`コマンドと判断」し、それを実行しようとしたために起きたエラー

シェルスクリプトを考えるときのポイントは

1. シェルスクリプトはすべてコマンドの羅列である
2. シンタックスエラーではなくコマンドエラーとして考える
3. **シェルスクリプトはコマンドライン・テンプレートである**
4. **最終的にどのようなコマンドが実行されるかイメージする**

### if文の使用例

```bash
if [ 0 -eq 0 ]; then
    echo "equal."
fi
```

条件式に使用している`[`もコマンド。`/bin/[`というコマンドである。したがって`[`の**前後は必ずスペースが必要になる。**それに続いている`0`や`-eq`もパラメータであるため、区切りとしてスペースが必要となる。
セミコロン`;`は、**同一行に複数コマンドを記述する場合に区切り**として使用する。C言語などとは異なり行末に必ずセミコロンを付ける必要はないが、同一行内に複数コマンドを記述する場合はセミコロンが必要となる。
また、`then`は本来、改行後に記述する必要があるが行の無駄なので`;`を使用して`if`と同一行内に記述するようにする。
**文法的にはセミコロンの前後のスペースは不要。**

```bash
#!bin/bash
# readコマンドでキーボードから入力した文字列を変数strに設定する

read str

# 変数は必ず""で囲んで使用する(変数に値が入っていない場合、""がないと文法エラーになるため)
if [ "$str" = "hoge" ]; then
    echo "hoge"
elif [ "$str" = "fuga" ]; then
    echo "fuga"
else
    echo "unknown"
fi
```
`elif`を増やして分岐を加えることもできる

### case文の使用例

```sh
#!bin/bash
case "$str" in
    "hoge" ) echo "hoge"
             echo "hoge" ;; # hoge hoge
    "fuga" ) echo "" ;;  #
    *) echo "unknow" ;; # unknown
esac
```

パターンの部分に正規表現は使用できないが、代わりにワイルドカード(すべての文字列と一致`*`と、任意の一文字と一致`?`)が使用可能

### for文の使用例

他の言語にあるforeach文と同様

```sh
for i in 0 1 2 3
do
  echo $i
done
```

### while文の使用例

while文のループ継続条件式には、if文と同様に`[`コマンドを使用可能である。
```sh
while [ "$str" = "" ]
do
    read str
done
```

無限ループするには`:`コマンド(ヌルコマンド)を指定する。`:`**コマンドは一切の処理を行わずに、ただ正常終了するだけのコマンド**

```sh
while : #ヌルコマンド(正常終了なため、永遠にtrueとなる)
do
  read str

  if [ "$str" = "end" ]; then
    break
  fi
done
```

このようにwhile文やif文の条件式には`[`コマンド以外の任意のコマンドが指定可能。それは、while文やif文が見ているのは条件式自体ではなく、**終了ステータス**というコマンドの実行結果を表す数値だから。

```sh
if grep 'hoge' hogefile >/dev/null 2>&1
  echo "hoge found."
fi
```

`>/dev/null 2>&1`を指定すると、コマンドの実行結果やエラーなどの出力をディスプレイに一切表示しないようになる(grepコマンドの-sqオプションでも同様の効果が得られる)
`>/dev/null`と`2>&1`は逆にしてはいけない。
さらに、「1」は標準出力、「2」はエラー出力を意味している。要するに`>/dev/null 2>&1`は、「2(エラー出力)」を「1(標準出力)」にまとめて、さらに出力先を「/dev/null(ゴミ箱)」に変更するという意味になる。

### 終了ステータス

「終了ステータス」は、コマンド実行終了時に変数`$?`へ自動的に設定される。**通常、コマンド実行成功の場合は「0」、コマンド実行失敗は「0以外」となる。**
touchコマンドで0バイトのファイルhogeを作成し、それをlsコマンドで参照してみる。

```sh
$ touch hoge
$ ls hoge
hoge
$ echo &?
0
```
直前にhogeファイルを作成しているので、当然lsコマンドは成功し、終了ステータスは0になる続けてrmコマンドでhogeファイルを削除してから、同様にしてlsコマンドを実行してみる
```bash
$ touch hoge
$ rm hoge
$ ls hoge
ls: hoge: No such file or directory
$ echo $?
2
```
今度はhogeファイルが存在しないため、lsコマンドの終了ステータスは0以外となっている。

## コマンドTips
---
### ファイル操作
---
#### 指定した容量のダミーファイルを作成する。
---
coLinux用のswapファイルを作成する時、自動バックアップスクリプトのベンチマークに使用するバックアップ対象ダミーファイルを作成する時、など、任意のサイズのダミーファイルを作成したい場合は`dd`コマンドを使用する。

```sh
dd if=/dev/zero of=DUMMY_FILE bs=1M count=*100*
```
->bsxcount(1MBx100)で100MBのダミーファイルを作る。
ddコマンドは
1. `if`に指定されたファイルを、
2. `bs`で指定されたサイズで、
3. `count`で指定された回数分読み込み
4. `of`で指定されてファイルにコピーする

コマンドである。

実際の実行結果は次の通り、

```sh
$ dd if=/dev/zero of=dummy bs=1M count=100
100+0 records in
100+0 recors out
104857600 bytes (105 MB) copied, 0.155313 seconds, 675 MB/s
$ ls -lh dummy
-rw-rw-r-- 1 sunone sunone 100M 5月31 01:27 dummy
```

`if`に`/dev/zero`を指定しているので、中身がすべてヌルキャラクタ(ASCIIの`0x00`)で100MBのダミーファイルが作成される。

#### 複数のファイルをまとめてリネームする

複数のファイルの拡張子を一括変換したいときは度、ふくすファイルのファイル名の一部を一括して変更したい場合は、mvコマンドではなくrenameコマンドを使用する

```sh
rename FROM_STRING TO_STRING TARGET_FILE
```
- 対象となるファイルのFROM_STRINGに該当する部分をTO_STRINGに置き換えてリネームする

```sh
$ ls
bar.htm  foo.htm  fuga.htm  hoge.htm
$ rename .htm .html *.htm
$ ls
bar.html  foo.html  fuga.html  hoge.html
```

#### diffコマンドに一時ファイルを作らずにコマンド実行結果をわたす。

diffコマンドは引数にファイル以外を指定することはできないため

```bash
$ diff 'command1` `command2`
```
のように、**コマンドの実行結果を直接渡すことはできない。**

通常、この`command1`と`command2`の実行結果をdiffコマンドで比較するには、一時ファイルに各コマンドの実行結果を出力し、その一時ファイルをdiffコマンドで比較することになる。
だが、**プロセス置換**を使用することで、一時ファイルを作成せずに、コマンドの実行結果を直接diffコマンドに渡すことができる。

```bash
$ diff <(command1) <(command2)
```

### プロセス

#### プロセスツリー形式で表示する

##### 全体表示

プロセスの親子関係をわかりやすく表示するにはpstreeコマンドを利用する

```bash
pstree -anpHプロセスID
```
- pstreeコマンドに`anpH`オプションと強調表示したいプロセスID(PID)をスペース無しで指定する
pstreeコマンドは実行中のプロセスの親子関係をツリー構造で表示するコマンド

特定のプロセスを強調表示したい場合は`H`オプションとともに対象のプロセスIDを指定する。強調表示が不要な場合は、`H`オプションとプロセスIDは不要

各オプションの詳細は以下の通り、
- -a
  - コマンドの引数を表示する
- -n
  - PIDでソートする
- -p
  - PIDで表示する
- -h
  - カレントプロセスとその先祖のプロセスを強調表示する
- -H\*プロセスID\*
  - 指定したPIDのプロセスを強調表示する。

## シェルスクリプトTips

### コーディングスタイル

#### スクリプトのヘッダを作成する

`@(#)`の記述と、スクリプトの使用方法、及び概要をファイルの前方にコメントとして記述しておくようにする。
`@(#)`はwhatコマンドで参照する情報を記述するための記号。

```sh
#!/bin/bash
#
# @(#) hoge.sh ver.1.0.0 2008.04.24
#
# Usage:
#   hoge.sh param1 param2
#     param1 - パラメータ1です.
#     param2 - パラメータ2です.
#
# Description:
#   hoge.shスクリプトです.
#
###########################################################################

# ここから処理を記述します.
echo "start..."
```

#### インデントは半角スペースが2つ

半角スペースが4つが理想ではあるが、シェルスクリプトはパイプ処理があるため、横に長くなりやすい。そのためインデントは少なめ。

#### | と <>前後のスペース

`|`は前後に1スペースを空ける
`>`は前に1スペース空ける
`<`は後ろに1スペース空ける

`<`と`<<`も`>`と同様
ちなみに、| や > 、>> および <、<< は前後にスペースが全くなくても文法エラーにはならない。

#### ifとthenは同一行に、セミコロンの直後にのみスペースを置く

```sh
if [ "$str" = "hoge" ]; then
  echo "strはhoge."
fi
```

#### for,whileのdoとdoneの頭を揃える

`if`の`then`場合とは異なり、`do`は`for`、`while`の直下行に記述する。そのほうが、`do`と`done`が揃うため可読性が高い。

#### 複数行の一括コメントアウト

: (ヌルコマンド)は一切の処理を行わずに終了するコマンドで、コメントアウトしたい箇所をこのコマンドへのヒアドキュメントとすることで、該当箇所の処理を無効化し、結果的にコメントアウトした場合と同様の結果を得ることができる。

```sh
: <<'#__COMMENT_OUT__'
echo "ここの処理は全て無効になります."

# hogeファイルは作成されません.
touch hoge

# 終了文字をシングルクォートで囲んでいるのでコマンド置換も行われません.
dummy=`touch fuga`

#__COMMENT_OUT__
```

#### なぜ`""`で囲むのか?

shは、クォート無しの変数を展開した後に、その中身をもう一度加工するから。加工自体は2つある。
- **単語分割**: 空白で区切って複数の変数に分ける
- **パス名展開**: `*`や`?`をファイル名に置き換える。

例:
```sh
file="my memo.txt"
rm $file # rm my memo.txt → 「my」と「memo.txt」の2つを消そうとする
rm "$file" # rm "my memo.txt"→ 意図通り1つのファイル
```

```sh
msg="*"
echo $msg # echo * #カレントディレクトリのファイル名一覧が出る
echo "$msg" # *がそのまま出る
```

#### $の使い方

`$`は変数専用ではなく、「個々をなにかの値に置き換える」という合図。後ろに続く括弧の種類で何に置き換えるのか変わる。

|書き方|名前|置き換わるもの|
|---|---|---|
|`$var`, `${var}`|変数展開|変数の中身|
|`$(コマンド)`|コマンド置換|コマンドを実行した結果|
|`$((式))`|算術展開|式を計算した結果|

## 自作コマンド作成の際のTips

コマンドには引数が存在する
```bash
mkpass 1 2 3
```
1,2,3は引数となっている。シェルスクリプト内ではこれらの引数をつぎのように変数として保持する
- 1つ目の変数:スクリプト名
  - `$0`
- 2つ目の変数: 1~番目の引数
  - `$1`,`$2`,...
- 引数の個数
  - `$#`
- 全引数(個々の区切りを保ったまま)
  - `"$@"`

コマンド起動時点で`$1`などが入っている。
