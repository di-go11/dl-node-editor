# feat:検証データの混同行列を表示する

## 問題点

セグメンテーションの学習では、クラスごとの IoU までしか表示していない。IoU が低いクラスがあっても、次のことが分からない。

| 分からないこと | 例(SegNet・3 クラスの学習。クラス 2 の IoU が 0.37) |
|---|---|
| どのクラスと取り違えているか | クラス 2 を背景(クラス 0)と間違えているのか、クラス 1 と間違えているのか |
| 見落としか、はみ出しか | クラス 2 の画素を拾えていない(再現率が低い)のか、ほかの画素までクラス 2 にしている(適合率が低い)のか |
| クラスの少なさ | クラス 2 の画素が検証データ全体のどれくらいか |

深さ(10/30/50/100 層)× 損失(Cross Entropy / Focal / Dice)の比較実験で、損失を変えたときに「何が」良くなったかを見るためにも、混同行列が要る。

## 方針

**C++ が評価のたびにすでに作っている混同行列を、そのまま(画素数で)送り、画面で表にする。**

- C++ の `TorchModelEvaluator::evaluate()` は、IoU などを出すために `[C, C]` の混同行列(行 = 正解、列 = 予測、ignore_index の画素は除外)を作っている。いまは集計した値だけを送り、行列は捨てている
- 正規化(割合)はせず**画素数のまま**送る。行ごとの割合(再現率の向き)・列ごとの割合(適合率の向き)・クラスの画素の割合は、画面で画素数から計算できる。送る側で片方に決めると、もう片方が出せなくなる
- エポックごとに DB に保存し、学習中の画面(最新のエポック)と「学習の記録」画面(選んだエポック)の両方で表示する

## 設計

### C++(ai-engine)

| 場所 | 変更 |
|---|---|
| `SegmentationMetricsConfig` | `std::vector<int64_t> confusionMatrix` を足す(行優先、長さ C×C) |
| `TorchModelEvaluator::evaluate()` | 作った `confusionMatrix` を行優先で詰める |
| `TrainingProtoMapper`(533 行付近) | `confusion_matrix` に詰める |

### proto(`training.proto`)

```proto
message SegmentationMetrics{
    double pixel_acc = 1;
    double miou = 2;
    double fw_iou = 3;
    double mean_class_accuracy = 4;
    repeated double per_class_iou = 5;
    // 検証データの混同行列(画素数)。行 = 正解のクラス、列 = 予測のクラス。行優先で長さ C×C
    // (C = per_class_iou の長さ)。ignore_index の画素は含めない。
    repeated uint64 confusion_matrix = 6;
}
```

- 古い ai-engine から届いたとき(空)も読めるように、Rust では「なし」として扱う

### Rust(api)

| 層 | 変更 |
|---|---|
| entities `SegmentationMetrics` | `confusion_matrix: Option<ConfusionMatrix>`。`ConfusionMatrix` は `Vec<Vec<u64>>`(C 行 C 列)を持ち、正方であることを `new` で確かめる |
| adapters `from_proto.rs` | 長さが `per_class_iou.len()²` なら `C` 行に分けて `Some`。空なら `None`。長さが合わなければ `None` にして警告をログに出す(学習は止めない) |
| DB | 新しい表 `segmentation_confusion_matrix`(マイグレーション `0006`) |
| `sql_recorder.rs` | エポックごとに C×C 行を書く |
| `sql_model_reader.rs` | `fetch_history` で読み、`EpochRecord` に載せる |
| DTO | `TrainingProcess`(進捗のストリーム)と `EpochRecord`(学習の記録)の segmentation の metrics に `confusion_matrix: number[][] \| null` |
| `openapi.yaml` | 上の 2 つのスキーマに足す |

```sql
-- 0006_segmentation_confusion_matrix.sql
CREATE TABLE segmentation_confusion_matrix (
    job_id      TEXT NOT NULL,
    epoch       INTEGER NOT NULL,
    true_class  INTEGER NOT NULL, -- 正解のクラス(行)
    pred_class  INTEGER NOT NULL, -- 予測のクラス(列)
    pixel_count INTEGER NOT NULL,
    PRIMARY KEY (job_id, epoch, true_class, pred_class),
    FOREIGN KEY (job_id, epoch) REFERENCES training_epochs(job_id, epoch)
);
```

- 行数は 1 エポックで C² 行。3 クラス × 200 エポックで 1,800 行、Pascal VOC(21 クラス)× 200 エポックで約 88,000 行。SQLite で問題ない量
- 既存の `segmentation_class_metrics` と同じく正規化した表にする(下の「決めること」1)

### フロント

**entity**(`entity/training/confusion-matrix.ts`。表示から切り離して単体でテストする)

| 関数 | 内容 |
|---|---|
| `rowRatios(matrix)` | 行ごとの割合(正解クラス c の画素のうち、各クラスと予測した割合)。対角が再現率 |
| `columnRatios(matrix)` | 列ごとの割合(クラス c と予測した画素のうち、正解が各クラスだった割合)。対角が適合率 |
| `classPixelRatios(matrix)` | クラスごとの画素の割合(行の合計 ÷ 全体) |

- 行(列)の合計が 0 のクラス(検証データに現れない・一度も予測されない)は、割合を `null` にして「—」と表示する(0 % と区別する)

**infrastructure**

- `http-training-progress.ts` / `http-trained-model-api.ts` の zod スキーマに `confusion_matrix` を足す(`null` と古い応答のキーなしの両方を受け付ける)

**presentation**(`components/metrics/ConfusionMatrixTable.tsx`)

```
混同行列(検証データ・エポック 200)   表示: (•) 正解ごとの割合  ( ) 予測ごとの割合  ( ) 画素数

                 予測 →
               クラス 0   クラス 1   クラス 2  | 画素の割合
正解 クラス 0  [ 99.6 %]     0.3 %      0.1 %  |  93.1 %
  ↓ クラス 1      9.8 %  [ 88.7 %]     1.5 %  |   5.2 %
     クラス 2     41.2 %     3.0 %  [ 55.8 %] |   1.7 %
```

- `<table>` で作り、行見出し(正解)・列見出し(予測)を `<th scope>` で付ける。対角のセルは枠で強調する
- セルの背景は 1 色の濃淡(割合が大きいほど濃い)。色だけに頼らず、数値を必ず書く
- 表示の切り替え: 正解ごとの割合(既定。見落としが分かる)/ 予測ごとの割合(はみ出しが分かる)/ 画素数
- クラスの呼び名は、いまのクラスごとの IoU と同じ「クラス 0」「クラス 1」…

**置き場所**

| 画面 | 表示するエポック |
|---|---|
| 学習中の画面(`ProgressPage`)の「クラスごとの IoU」の下 | 最新のエポック |
| 「学習の記録」画面(`TrainedModelHistoryPage`)の表の上 | 既定は最も良かったエポック(記録がなければ最後のエポック)。エポックを選んで切り替えられる(下の「決めること」2) |

- 混同行列のない記録(このissueより前の学習・分類タスク)は「この学習には混同行列が記録されていません」と出す

## テスト

- C++
    - `model_evaluator_test`: 予測と正解が分かっている小さなバッチで、混同行列の各セルの画素数が合う。ignore_index の画素は数えない
    - `training_proto_mapper_test`: `confusion_matrix` が行優先で C×C 個入る
- Rust
    - `from_proto`: 長さ C² なら C 行に分かれる / 空なら `None` / 長さが合わなければ `None`
    - `sql_recorder` → `sql_model_reader` の往復で、混同行列がエポックごとに戻る。古い記録(表に行がない)は `None`
    - DTO の JSON が `confusion_matrix: [[...], ...]` / `null` になる
- フロント
    - `confusion-matrix.test.ts`: 行・列ごとの割合、画素の割合。合計 0 の行(列)は `null`
    - zod スキーマ: `confusion_matrix` あり / `null` / キーなしを読める
    - `ConfusionMatrixTable`: 見出しと数値、表示の切り替え、混同行列がないときの文言
    - 「学習の記録」画面の既定のエポック: 最も良かったエポックの記録があればそのエポック、なければ最後のエポック
    - contract test(`openapi.yaml` と型の一致)

## 決めること

1. **DB への保存の形**
    - 案 A(おすすめ): 正規化した表(上の `segmentation_confusion_matrix`)。既存の `segmentation_class_metrics` と揃い、SQL で特定のセルだけ引ける
    - 案 B: `segmentation_epoch_metrics` に JSON の文字列で 1 列足す。書き込みは簡単だが、ほかの表と作りが揃わない
2. **「学習の記録」画面で表示するエポック** → **決定: 最も良かったエポックを既定にし、エポックを選ぶ欄で切り替えられるようにする**
    - 推論に使う `_best.pt` は、C++ の `BestMetricTracker` が mIoU で選んだエポックの重み。そのエポックの混同行列なら、実際に使うモデルがどこを間違えるかが分かる。最後のエポックが過学習の後だと、使わない重みの混同行列を見ることになる
    - 最も良かったエポックは、C++ が決めたものを使う。Rust・フロントで DB の mIoU の最大値から計算し直さない。次の 2 つで `_best.pt` とずれるため
        - 同じ mIoU のエポックが複数あるときに、最初と最後のどちらを取るか
        - 再開(resume)のときに、以前のベストを引き継ぐ扱い
    - 最も良かったエポックを C++ から送って DB に記録する作業は、別の issue「最も良かったエポックの記録と表示」で行う([mIoU のグラフの issue](../2026-11-27/mIoUとクラスごとのIoUの推移グラフ.md) の対象外にある「最も良かったエポックの印」と同じもの)。**その issue が入るまでは、最後のエポックを既定にする**
    - 学習中の画面は、これまでどおり最新のエポックを表示する
    - 全エポックの混同行列を一度に並べることはしない(200 個並べても見比べられない)。エポックごとの変化は、対角(再現率)の推移を折れ線で見る形にする(下の「対象外」)
3. **保存するエポック** → **決定: 毎エポック**
    - 3 クラス × 200 エポックで 1,800 行。DB の負担は小さい
    - 最後と最も良かったエポックだけにすると、あとで「最も良い」の基準(mIoU 以外の指標など)を変えたとき、学習を取り直すしかなくなる

## 対象外

- 分類タスクの混同行列(評価の作りが違うので、必要になったら別の issue にする)
- クラスごとの適合率・再現率・F1 の表(混同行列から計算できるので、この issue の後に別の issue で足す)
- クラス名の表示(labelmap のクラス名を DB に保存する作業が要る。`segmentation_class_metrics` のコメントにある課題と一緒に扱う)
- 混同行列の CSV / 画像での保存
- 最も良かったエポックを C++ から送り、DB に記録する作業(別の issue「最も良かったエポックの記録と表示」)
- クラスごとの再現率(混同行列の対角)の推移のグラフ(mIoU のグラフができた後に、同じ作りで別の issue で足す)

## 完了条件

- 学習中の画面で、最新のエポックの混同行列が表示され、エポックごとに更新される
- 「学習の記録」画面で、選んだエポックの混同行列が表示される。開いたときは最も良かったエポック(記録がなければ最後のエポック)が選ばれている
- 正解ごとの割合・予測ごとの割合・画素数を切り替えられ、正解ごとの割合の対角が再現率と一致する
- このissueより前の学習の記録を開いても壊れず、「混同行列が記録されていません」と出る
- C++・Rust・フロントのテストと contract test が通る
