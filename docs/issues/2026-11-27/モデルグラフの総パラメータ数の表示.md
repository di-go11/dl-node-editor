# feat:モデルグラフの総パラメータ数を表示する

## 問題点

エディタでモデルを組んでも、学習で更新されるパラメータ(重み)がいくつあるかが画面で分からない。いまは [重みと計算量の見積もり.md](../../../apps/backend/ai-engine/docs/重みと計算量の見積もり.md) のように、層の構成から手で計算するしかない。

| 分からないこと | 例 |
|---|---|
| モデルの大きさ | SegNet は 3×3 Conv の重みだけで約 1,644 万。チャンネル数を半分にすると約 1/4 になるが、組みながらは確かめられない |
| 比較実験の条件 | 深さ(10/30/50/100 層)を変える実験で、各構成のパラメータ数を表に書くのに、毎回手で計算している |
| どの層が重いか | 重みの大半は 512 チャンネルの段にあるが、ノードを選んでもその層の数は出ない |

## 方針

**フロントで、各ノードのパラメータ(チャンネル数など)から計算して、グラフの情報(`GraphSummary`)に出す。サーバーには問い合わせない。**

- 重みの数は、ノード自身のパラメータだけで決まる。Conv2D は `in_channels` / `out_channels` / `kernel_size`、BatchNorm は `num_features`、Linear は `in_features` / `out_features` / `bias` を持っている。形の推論(上流のチャンネル数や H / W)は要らない
- 手元で計算するので、パラメータを変えるたびにすぐ数が変わる。学習の前に ai-engine を呼ぶ必要がない
- C++(libtorch)の `parameters()` と数が合うことは、同じグラフで両側のテストに同じ期待値を書いて確かめる(下の「テスト」)

### 数えるもの

「学習で更新されるパラメータ」= `IModel::parameters()` が返すテンソルの要素数の合計。

| 層 | 数 | 根拠(C++) |
|---|---|---|
| Conv2D | `out × in × k × k + out` | `TorchConv2DLayer` は `Conv2dOptions` の既定(bias あり)。`Conv2DSpec` に bias の指定はない |
| BatchNorm | `2 × num_features`(γ と β) | `TorchBatchNormLayer` は `BatchNormOptions` の既定(affine あり)。running mean / var は勾配で更新しないバッファなので数えない |
| Linear | `out × in`(`bias` が true なら `+ out`) | `TorchLinearLayer` は `LinearOptions(...).bias(params.bias)` |
| それ以外 | 0 | Pooling / IndexedPooling / Unpooling / Upsample / Activation / Concat は重みを持たない。Add の `alpha` は固定の係数で、学習しない |

- **グラフのすべてのノードを数える**。出力につながっていないノードも、C++ の `TorchModel` は `nodes` の並び順で層を作るので、重みを持つ(checkpoint にも入る)
- 編集の途中で値が数値でない(`readNumberParam` が `undefined`)ノードがあれば、合計は出さずに「—」にし、理由を添える。一部だけ足した数を出すと、正しい値と見分けられないため

## 設計

### entity

| 場所 | 変更 |
|---|---|
| `node-catalog/node-type.ts` の `NodeTypeDefBase` | `countParameters?: (spec: NodeSpec) => number \| undefined` を足す。重みを持たない種類は書かない(0 として扱う) |
| `node-catalog/entries/conv2d.ts` / `batch-norm.ts` / `linear.ts` | 上の表の式で `countParameters` を書く。値が読めなければ `undefined` |
| `model-graph/parameter-count.ts`(新規) | `countTrainableParameters(graph, catalog)`。結果は `{ kind: 'ok', total, byNodeId }` か `{ kind: 'unknown', nodeIds }`(値が読めないノードの ID) |

- 新しい層を足すときは、カタログのその種類に `countParameters` を書くだけで済む(`node-spec.ts` の「カタログに 1 件足すだけ」の方針に合わせる)
- 合計は `number` で持つ。2^53 を超えるモデルは扱わない

### presentation

`GraphSummary` の「接続数」の下に 1 行足す。

```
ノード数          42
接続数            48
パラメータ数      1,234,567(約 123 万)    ← 書式の例
モデルの出力      dec1_conv2.y
```

- 3 桁ごとにカンマを入れ、1 万以上なら「約 ○ 万」、1 億以上なら「約 ○ 億」を添える(`Intl.NumberFormat('ja-JP')` を使う)
- 値が読めないノードがあるときは「— (値が入っていないノードがあります: enc2_conv1 ほか)」
- 見出しの横に、「学習で更新される重みの数。BatchNorm の running mean / var は含めない」という説明(`hint`)を付ける

## 段階

1. **entity**: カタログの `countParameters` と `countTrainableParameters`、そのテスト
2. **C++ のテスト**: 同じグラフで `parameters()` の要素数の合計が期待値と一致することを確かめる
3. **presentation**: `GraphSummary` に表示する
4. **確認**: 下の完了条件

## テスト

- フロント
    - 各カタログの `countParameters`: Conv2D(例: 3→64、k3 で 1,792)、BatchNorm(64 で 128)、Linear(bias あり / なし)。値が数値でなければ `undefined`
    - `countTrainableParameters`: 重みのない層だけなら 0。出力につながっていないノードも数える。値が読めないノードがあれば `unknown` とその ID
    - 共通の期待値: Conv2D・BatchNorm・Linear(bias あり・なし)を含む小さなグラフの合計(下の C++ のテストと同じグラフ、同じ値)
    - `GraphSummary`: 数の書式(カンマ、「約 ○ 万」)、「—」の文言
- C++
    - `trainable_parameter_count_test`(新規): 上と同じグラフを `ModelGraphBuilder` → `TorchModel` で作り、`parameters()` の `numel()` の合計が期待値と一致する
    - 両方のテストのコメントに、もう片方のテストの場所を書く。libtorch の既定(bias / affine)が変わったり、層を足して式を書き忘れたりしたときに、C++ 側のテストで気づけるようにする

## 決めること

1. **ノードごとの数の表示**
    - 案 A(おすすめ): ノードを選んだときのプロパティパネルに「この層のパラメータ数」を出す。`byNodeId` を使うだけで、どの層が重いかが分かる
    - 案 B: キャンバス上のノード(`ModelNode` の要約)にも出す。一目で分かるが、ノードの表示が混み合う
2. **重みのメモリの目安も出すか**
    - 案 A(おすすめ): 出さない。この issue はパラメータ数だけにする
    - 案 B: 「float32 で約 66 MB」のように、パラメータ数 × 4 バイトを添える。Adam で学習するとその約 4 倍になるなど、optimizer によって変わるので、学習設定と合わせて別の issue で扱うほうがよい

## 対象外

- 「学習の記録」画面での、学習したモデルのパラメータ数の表示(記録したグラフから計算するか DB に保存するかを決める必要がある。比較実験の表に使うなら、別の issue で足す)
- 計算量(FLOPs)と活性化のメモリの見積もり(入力の H / W と形の推論が要る。重みの数と違ってノードのパラメータだけでは決まらない)
- 学習しないパラメータ(凍結した層)の区別(いまは凍結の機能がない)

## 完了条件

- エディタで何も選んでいないとき、グラフの情報にパラメータ数が出て、ノードのパラメータを変えるとすぐ変わる
- 値が入っていないノードがあるときは「—」と理由が出る
- フロントと C++ のテストで、同じグラフのパラメータ数が同じ期待値と一致する
