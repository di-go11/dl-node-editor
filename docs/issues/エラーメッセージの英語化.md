# chore:エラーメッセージの英語化

## やること

バックエンド(ai-engine の C++、api の Rust)のエラーメッセージを、すべて英語にする。コメントは日本語のままでよい。

## 問題点

エラーメッセージに日本語と英語が混ざっている。

- Rust(api)は `#[error("device type is unspecified")]` のように英語が大半で、日本語は 5 か所だけ
- C++(ai-engine)は大半が日本語(`throw std::invalid_argument("lr_scheduler: 学習データのバッチ数が 0 です")` など)

C++ の例外メッセージは `TrainingServiceImpl.cpp` で `grpc::Status(..., e.what())` としてそのまま gRPC のステータスメッセージになり、Rust 側に渡る。言語が混ざっていると、ログやエラーをまとめて読むときや検索するときに不便。

## 対象外

- **コメント**: 日本語のままにする。
- **テストの説明文**: `check(条件, "説明")` の第 2 引数など(`ai-engine/tests/` 内の約 480 行)。テストの説明で、エラーメッセージではないため。
- **フロントエンド**(`apps/frontend/src/`): `throw` / `Error(...)` で日本語を使っている箇所が約 47 行ある。利用者(研究室の後輩)に画面で見せる文言を含むため、英語にするかは別に決める。

## 英語にするときの書き方

1. **どこで起きたかを示す接頭辞は残す**: `lr_scheduler: `、`TrainingJobManager: `、`readModelGraph: ` など、いまある接頭辞はそのまま使う。
2. **値は今と同じように埋め込む**: 数値・パス・ID を消さない。
3. **文の形にそろえる**: 接頭辞の後は小文字で始め、最後にピリオドを付けない(Rust のエラーメッセージの慣習。Rust 側の既存のメッセージもこの形)。
4. **直し方が分かるメッセージでは、直し方も残す**: 日本語版の「〜してください」は英語でも残す。
5. **`[warn]` などログの接頭辞はそのまま使う。**

### 例

| 現在 | 英語にした後 |
|---|---|
| `lr_scheduler: 学習データのバッチ数が 0 です` | `lr_scheduler: training data has 0 batches` |
| `lr_scheduler: warmupEpochs は総エポック数より小さくしてください` | `lr_scheduler: warmupEpochs must be less than the total number of epochs` |
| `TrainingJobManager: ジョブ <id> は存在しません` | `TrainingJobManager: job <id> does not exist` |
| `resume が指定されましたが、再開用の checkpoint がありません: <path>` | `resume was requested, but no checkpoint to resume from was found: <path>` |
| `未対応のLossConfig型です` | `unsupported LossConfig type` |
| `DATASET_UPLOAD_MAX_MIBはMiB単位の整数で指定してください: {v}` | `DATASET_UPLOAD_MAX_MIB must be an integer in MiB: {v}` |

## 進め方

1. Rust の 5 か所を直す(数が少ないので先に片付ける)。
2. C++ を、上の表の順にディレクトリ単位で直す。ファイル数が多いので、`entities` → `application` → `adapters` → `infrastructure` → `api` のように層ごとに分けてコミットしてもよい。
3. テストを直す(`graph_shape_inference_test.cpp:383` など)。

## 確認方法

- C++: ビルドしてテストを実行し、すべて通ること(`cmake --build build -j2`、`ctest --test-dir build --output-on-failure -j2`)。
- Rust: `cargo test` がすべて通ること。
- 次のコマンドで、コメントを除いたコードに日本語の文字列が残っていないこと(コメントだけの行は除いている。行末コメントに日本語がある行は出てくるので、目で見て除く):

  ```bash
  cd apps/backend
  grep -rnP --include=*.cpp --include=*.hpp --include=*.h --include=*.rs \
    --exclude-dir=build --exclude-dir=target \
    '"[^"]*[\x{3040}-\x{30ff}\x{4e00}-\x{9fff}][^"]*"' ai-engine/src api \
    | grep -vP '^\S+:\d+:\s*(//|\*)'
  ```

## 今後のルール

新しく書くエラーメッセージは英語にする。この方針は、[C++の命名規則の統一.md](C++の命名規則の統一.md) と同じように、決まった時点で規約として残す。
