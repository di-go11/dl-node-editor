# feat:学習設定でデータセットを一覧から選択できるようにする(フロントエンド)

## 問題点

- 現在: 学習設定フォーム(`TrainingForm.tsx`)の「データセットのパス(サーバー上)」はテキスト入力で、サーバー上のパスを手で打つ必要がある
    - パスを知らないと学習を始められない。打ち間違いは学習開始後(C++側の読み込み時)まで分からない
    - クライアントから任意のパスを送れてしまう(`データセットアップロード機能とデータ選択機能.md` で挙げたセキュリティ上の問題)
- 新規: アップロード済みのデータセットを一覧から選び、選んだデータセットの ID をサーバーへ送る。パスはサーバー側で DB から引く

## 前提(バックエンド): 実装済み(ブランチ `feat/dataset-id-selection`)

API からサーバー上のパスをなくした。フロントはパスを送らず、受け取らない。

| API | 変更 |
|---|---|
| `GET /api/v1/datasets` | 一覧。応答は `{"datasets": [{dataset_id, dataset_name, dataset_type, created_at}]}`。パスは返さない |
| `POST /api/v1/trainings`, `POST /api/v1/trainings/validate` | `dataset_path` の代わりに `dataset_id`(必須)を受け取る。`dataset_path` だけを送ると 422 |
| `POST /api/v1/trainings` のエラー | `dataset_id` が空、または登録されていない → 422(本文なし) |
| `GET /api/v1/models/{model_id}/config` | `dataset_path` を返さなくなった。データセットの情報は返さない |
| `POST /api/v1/models/{model_id}/resume` | `dataset_path` を受け取らない(送っても無視)。データセットは前回のまま |

## 状態: 作業 1〜6 は実装済み(ブランチ `feat/dataset-id-selection`、フロントとバックエンドを同じブランチで変更)

- 決めたこと
    - UI はプルダウン(`DatasetField.tsx`)。選択肢は「名前(形式・登録日)」。0 件・取得失敗・一覧にない ID(削除済み)の表示と、再読み込みボタンあり
    - 保存ファイルは **version 2** にし、`training` に `dataset_id` を保存する(開き直すと選んだデータセットが戻る)
        - version 1 のファイルと C++ の設定ファイル(`test_segnet_dag.json`)も開ける。`dataset_path` は読み捨て、データセットは未選択になる(`migrate.ts` の `migrateV1toV2`)
    - 再開画面ではデータセット欄を出さず、「前回の学習と同じものを使う」と表示する
- 残り: 実サーバーでの確認(下の「確認」の 2 つ目)

## 2. データセット一覧を取得する層を追加

既存の学習済みモデル一覧(`trained-model-api.ts` / `http-trained-model-api.ts`)と同じ構成にする。

- infrastructure/http: `http-dataset-api.ts`。応答は zod で検証し、snake_case → camelCase に変換する

- テスト: 正常な応答 / 空の一覧 / 500 / 形式が不正な応答

## 3. 学習設定フォームにデータセットの選択欄を追加

対象: `presentation/components/training-form/TrainingForm.tsx`, `presentation/pages/TrainingSettingsPage.tsx`

- テキスト入力をやめ、一覧から 1 つ選ぶ UI にする。表示はデータセット名を主にし、形式(`dataset_type`)と登録日時を添える
- UI の形はどちらかにする(実装時に決める)
    - **プルダウン(`<select>`)**: フォームの他の項目と並びが揃い、実装が小さい。件数が少ないうちはこれで十分
    - **リスト(ラジオボタン付きの行)**: 形式・登録日時を並べて見比べやすい。件数が増えたら検索・並び替えを足せる
- 状態ごとの表示
    - 読み込み中: 選択欄を無効化し、読み込み中であることを表示する
    - 取得失敗: エラーメッセージと再読み込みボタン。学習開始ボタンは押せないようにする
    - 0 件: 「データセットがありません。先にアップロードしてください」と表示する
- 一覧は画面を開いたときに 1 回取得する。アップロード画面ができたら、アップロード後に再取得する

## 4. 学習設定の型と検証を `datasetId` に変更

対象: `entity/training/training-settings.ts`, `entity/validation/validate-training.ts`

- `TrainingSettings.datasetPath` を `datasetId` に置き換える(初期値は未選択)
- 検証: 未選択ならエラー(「データセットを選択してください」, フィールド名 `dataset_id`)
- ドキュメントの保存・読み込み(`save-document` / `open-document`)で、学習設定に `datasetPath` を含む古いファイルを開いたときの扱いを決める
    - 案: `datasetPath` は読み捨てて未選択にする(パスから ID は引けないため)

## 5. 学習開始リクエストを `dataset_id` に変更

対象: `infrastructure/http/rust-training-request.ts`, `entity/training/proto-json/convert.ts`

- リクエストの `dataset_path` を `dataset_id` に置き換える
- 選んだデータセットが削除済みなどでサーバーに見つからなかったときのエラーを、フォームの `dataset_id` 欄に表示する

## 6. 学習再開画面での扱い(案 A で決定、バックエンドは対応済み)

対象: `infrastructure/http/rust-training-request.ts`(再開リクエスト・設定の取得), 再開画面

- 再開ではデータセットを変えられない(サーバーが前回のデータセットをそのまま使う)。再開画面ではデータセットの欄を出さない
    - 設定の取得 API はデータセットの情報を返さないので、前回どのデータセットだったかは表示できない。必要になったら API の追加を検討する
- 再開リクエストから `dataset_path` を外す
- 再開でも選び直せるようにする(案 B)には、再開 API に `dataset_id` を追加する必要がある。必要になったら別に検討する

## 追加: データセット一覧とアップロードの画面(実装済み)

- エディタのヘッダの [データセット] ボタンから `/datasets` を開く。名前・形式・登録日時の一覧
- [+ 追加] で zip・名前(初期値は zip のファイル名)・形式を入れて `POST /api/v1/datasets/upload` に送る。成功したら一覧を取得し直す
- 400 / 413 / 500 は理由を表示し、フォームを残す(送り直せる)
- 今後の候補: アップロードの進捗バー(fetch では送信の進捗が取れないので XMLHttpRequest が必要)、データセットの削除
