# fix:データセットアップロードの受信上限と解凍処理

## 問題点

- 現在: `POST /api/v1/datasets`(zipアップロード)はRust側で実装済みだが、
    - nginx経由だと1MBを超えるzipが `413 Request Entity Too Large` で拒否される
    - zipの解凍が非同期ランタイムのスレッドを塞ぐので、解凍中は他のAPI(学習進捗のSSEなど)が遅れる
- 新規: ブラウザから大きいデータセットをアップロードでき、解凍中も他のAPIが普段どおり動くようにする

## 1. nginxの受信上限を広げる

対象: `.deploy/nginx.conf`

- `location /api/` に `client_max_body_size` がなく、nginxの標準の1MBが上限になっている
- Rust側の上限 `MAX_DATASET_UPLOAD_BYTES`(`crates/adapters/src/http/router.rs`、10GiB)と値を揃える
- `proxy_request_buffering off` も付ける。付けないとnginxがzip全体を一度コンテナ内のディスクに書き出してからapiへ送るので、ディスク使用量がさらに増え、アップロード完了までapi側の処理も始まらない

```nginx
location /api/ {
    proxy_pass http://api:8080;
    proxy_buffering off;
    proxy_read_timeout 1h;
    client_max_body_size 10g;      # Rust側の MAX_DATASET_UPLOAD_BYTES と揃える
    proxy_request_buffering off;   # 受け取りながらapiへ流す
}
```

- 検討: `/api/` 全体に効かせると他のAPIも10GBまで受け付けてしまう。`location = /api/v1/datasets` を別に作り、そこだけ上限を広げる方が安全
- 確認: 1MBを超えるzipをnginx経由(ポート25812)で送り、`201 Created` が返ること

```bash
curl -i -F file=@sample.zip -F name=sample -F type=pascal_voc http://localhost:25812/api/v1/datasets
```

## 2. zipの解凍を `spawn_blocking` に移す

対象: `crates/adapters/src/dataset/dataset_saver.rs`

- `FileDatasetSaver::save` は `async fn` だが、中で同期I/O(`std::fs` と `zip`)の `save_archive` をそのまま呼んでいる
- 解凍している間(数GBなら数十秒〜数分)tokioのワーカースレッドが1本ふさがり、そのスレッドに載っている他のリクエスト・SSE配信・進捗の記録が止まる
- 修正案:

```rust
impl DatasetSaver for FileDatasetSaver {
    async fn save(&self, zip_path: &Path, dataset_id: &DatasetId) -> Result<PathBuf, DatasetError> {
        // spawn_blocking に渡すクロージャは 'static が必要なので、借用ではなく所有した値を move する
        let zip_path = zip_path.to_path_buf();
        let root = self.dataset_root.clone();
        let id = dataset_id.as_str().to_string();
        tokio::task::spawn_blocking(move || save_archive(&zip_path, &root, &id))
            .await
            .map_err(|e| DatasetError::SaveFailed(e.to_string()))? // 解凍タスクが panic した場合
            .map_err(DatasetError::from)
    }
}
```

- `spawn_blocking` に必要なtokioの `rt` featureはadaptersに入っている
- `save_archive` には単体テストがまだないので、一緒に追加する
    - 普通のzip / 直下がディレクトリ1つだけのzip(中身がルートになること)
    - 壊れたzip(`.tmp-<id>` が残らないこと)
    - `../` を含むパス(Zip Slip、`UnsafePath` になること)
