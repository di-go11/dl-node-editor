# 深層学習 備忘録

このプロジェクト(ai-engine)を設計・実装する上での深層学習まわりの整理メモ。
「何がモデルの構造で、何が学習のときだけ使うものか」を混同しないための土台。

## 1. 学習で登場する要素の 4 分類

深層学習の学習ループに登場する要素を、役割で 4 群に分ける。

### A. モデルの構造(`ModelGraph`。推論時も必要・保存対象)

入力 → 出力の変換の連鎖。学習可能パラメータを持ち、`torch::save` で保存して推論時にそのまま再構築する対象。

| 要素 | 役割 | 学習パラメータ | このコードでの担当 |
|---|---|---|---|
| Conv2D / Linear / Pooling / BatchNorm 層 | 入力→出力の変換 | あり(weight/bias, running stats) | `Conv2DParams` 等 → `TorchConv2DLayer` |
| 隠れ層の活性化(ReLU など) | 非線形性の付与。順序に意味がある | 原則なし | `ActivationParams` → `TorchActivationLayer`(`graph.layers` に挟む) |
| 層の形状(in/out channels, kernel, stride) | アーキテクチャの定義 | — | `Conv2DParams` |
| 最終出力チャンネル数(= クラス数) | 出力の意味を決める。**タスク/ラベルに従属** | — | `main.cpp` で `ColorLabelMap::entryCount()` から |

### B. 学習のみで使う(推論時は不要)

学習が終われば捨ててよい(optimizer 状態だけは再開用に残すことがある)。

| 要素 | 役割 | 状態を持つ | 保存 | このコードでの担当 |
|---|---|---|---|---|
| Loss(CrossEntropy 等) | 出力と正解の乖離をスカラーで測る。逆伝播の起点 | 通常なし | しない | `ILoss` → `CrossEntropy` |
| Optimizer(Adam 等) | 勾配でパラメータを更新 | あり(moment 等) | チェックポイントには含めることが多い | `IOptimizer` → `AdamOptimizer` |
| learning rate / weight decay | 更新幅・L2 正則化の強さ | — | 設定として | `AppConfig`(`.config`) |
| LR スケジューラ | 学習中に lr を変化させる | あり | 含めることが多い | 未実装 |
| 学習ループ制御(zero_grad→backward→step の順、epoch 反復) | 更新手続き | — | — | `TorchModel::train` / `TrainModelUsecase` |
| 勾配クリッピング / AMP / EMA | 学習の安定化・高速化 | 一部あり | 一部 | 未実装 |

### C. データパイプライン(学習・評価で使う。モデルではないが再現必須)

前処理は「モデルの一部ではないが、学習時と推論時で完全に一致させる必要がある」。デプロイ時にモデルと一緒に前処理設定を固める理由がこれ。

| 要素 | 役割 | 推論時 | このコードでの担当 |
|---|---|---|---|
| Dataset / Repository | サンプル(画像・正解)の供給 | 不要(推論は単発入力) | `VocDatasetRepository` |
| 前処理: decode → resize → normalize | 生データ→モデル入力テンソル | **必要(学習と同一のものを)** | `OpenCvImageDecoder` / `OpenCvImageResizer` / `ImageNormalizer` |
| Augmentation(flip, random crop 等) | 汎化性能向上のためのランダム変形 | **不要**(学習時のみ) | 未実装 |
| LabelMap(色→クラス ID) | アノテーション画像の解釈 | 必要(可視化・評価) | `LabelMapFileReader` → `ColorLabelMap` |
| バッチ→テンソル変換 | `[N,C,H,W]` へ結合 | 必要 | `BatchTensorConverter` |
| ignore_index / padding 値(255) | 損失・評価から除外する画素の印 | — | `ResizePreprocessorFactory` / `CrossEntropy` |

### D. 設定・ハイパーパラメータ(`TrainParam`, `AppConfig`)

| 要素 | 役割 | 担当 |
|---|---|---|
| epoch 数 / batch size | 学習ループの反復回数・粒度 | `TrainParam` ← `AppConfig` |
| 入力サイズ(width/height) | 前処理とモデル入力の整合 | `AppConfig` → `ResizePreprocessorFactory` |
| アスペクト比ポリシー(Letterbox 等) | リサイズ方式 | `AspectRatioPolicy` |

## 2. 分類の判断基準

| 問い | Yes なら |
|---|---|
| 学習可能パラメータを持つ / forward の変換連鎖に入る | **A. 構造** |
| 推論時には一切使わない | **B. 学習のみ** |
| データを供給・整形するが変換連鎖ではない | **C. パイプライン** |
| 数値・列挙で挙動を調整するだけ | **D. 設定** |

## 3. 境界にあるもの(注意)

| 要素 | どっち? | 理由 |
|---|---|---|
| 最終活性化(softmax/sigmoid) | B / 推論寄り | CrossEntropy 等では学習時に不要(loss 内蔵)、推論時のみ適用。**A(構造)には入れない** |
| クラス数 / 出力チャンネル数 | A だが従属 | 構造の一部だが、値は LabelMap(C)が決める → 単一の参照元を LabelMap にする |
| Optimizer の状態 | B だが保存対象 | モデルではないが、学習再開には必要 |
| 前処理 | C だが推論必須 | モデルと別だが、学習と同一設定を推論に持ち込む必要 |

## 4. GUI(ブロックプログラミング)での扱い

| 区分 | GUI での見せ方 |
|---|---|
| 構造(層 + 隠れ活性化) | 配置・接続できる**グラフのブロック**。順序も自由 |
| 学習の駆動(Loss / Optimizer / lr など) | グラフ外の**学習設定パネル**。種類 + ハイパーパラメータを選択 |
| 最終活性化 | グラフ末尾のブロックにはしない。Loss 選択から自動決定 or 推論設定 |

### 1 ステップの実行順

```
入力テンソル
  → [グラフの層を forward で順に適用] → 最終層の生ロジット
  → Loss(ロジット, 正解) → スカラー損失      ← forward の「後」
  → optimizer.zero_grad()
  → loss.backward()                          ← 勾配を計算
  → optimizer.step()                          ← Optimizer はここ(backward の後)
```

- Loss は forward の直後(最終層出力を消費)
- Optimizer は forward の後ではなく **`backward()` の後**。データフローには乗らず `model.parameters()` を舐めて更新する
- Optimizer は「グラフが確定してパラメータが決まった後」に構築する(`model.parameters()` を渡すため)

### GUI 上の整合制約

- Loss の選択がグラフに制約をかける:
  - 最終層の出力チャンネル数 = クラス数(LabelMap から自動)
  - CrossEntropy / BCEWithLogits を選んだら、グラフ末尾に softmax ブロックを置かせない(自動で無効化)

## 5. 損失関数と最終活性化の対応

名前に `WithLogits` が付く損失は活性化を内部で融合している(数値安定性のため)。それ以外は自分で掛ける必要がある。

| 損失 | 期待する入力 | 手前の活性化 |
|---|---|---|
| CrossEntropy(多クラス) | 生ロジット | 不要(log_softmax を内蔵) |
| BCEWithLogitsLoss(2 値・マルチラベル) | 生ロジット | 不要(sigmoid を内蔵) |
| Focal Loss(一般的な実装) | 生ロジット | 不要 |
| NLLLoss | 対数確率 | log_softmax を明示 |
| BCELoss | 確率 [0,1] | sigmoid を明示 |
| Dice / IoU Loss(セグメンテーション) | 確率 [0,1] | softmax / sigmoid を明示 |
| MSE / L1(回帰・AE・深度) | target と同じ空間 | target 次第(正規化画像なら sigmoid、無制約なら無し) |

**logit 融合型の損失の手前に、値を潰す活性化(ReLU/sigmoid/tanh/softmax)を置かない。**
`CrossEntropy` の手前で ReLU を掛けると、負のロジット(= 低確率の情報)が 0 に潰れ、勾配も消え、学習が壊れる。

### 活性化の 2 種類

| 種類 | 位置 | 損失との関係 |
|---|---|---|
| 中間活性化(層と層の間の ReLU など) | ネットワーク内部、conv と conv の間 | 損失に関係なく常に入れる。`graph.layers` に活性化層として挟む |
| 最終活性化(出力を確率に変える softmax / sigmoid) | ネットワークの一番最後 | 損失と強く結合。**学習時はスキップ(logit 融合型の場合)、推論時のみ適用** |

## 6. 重み保存とチェックポイント

| | 中身 | 用途 |
|---|---|---|
| 重み(weights)だけ | 各層の weight / bias、BatchNorm の running stats | 学習済みモデルの**推論・デプロイ・配布** |
| チェックポイント(checkpoint) | 重み + **optimizer の状態(Adam のモーメント等)** + epoch / iteration + LR スケジューラ状態 + (任意)best loss / RNG 状態 | 学習の**中断・再開**、ベストモデルの保持、実験の分岐 |

- Adam は各パラメータごとに 1 次・2 次モーメント(移動平均)を持つ。これが無いと再開時に更新の慣性がリセットされ loss が跳ねる → チェックポイントには optimizer 状態を含める。
- interface 設計では `save(model, path)` だけでなく、後で optimizer 状態や epoch を足せるよう `Checkpoint` 型を想定しておくと破壊的変更にならない。

## 7. 関連する設計判断

- Loss / Optimizer は `graph.layers` に埋め込まない。学習ユースケースに注入する戦略(`ILoss` / `IOptimizer`)。
- 「学習に関わるもの全般を保存する」汎用 interface(`ISave` など)は作らない。関心事ごとに focused な interface を分ける(モデル保存 = `IModelStore`、メトリクス保存は将来 `IMetricsSink` を別途)。
- 本当に共通なのは低レベルの機構(パス処理・アトミック書き込み・フォーマット)。それは infra 層のヘルパーとして合成で共有する。
