# 重みと計算量の見積もり

モデルの「重み(パラメータ)の数」「計算量(FLOPs)」「学習時のメモリ」を、層の構成から手で見積もるためのノート。
モデル構造(SegNet / dilation の入れ方 / チャンネル数)を決めるときの判断材料にする。

---

## 1. 重み(パラメータ)とは

学習で更新される値のこと。`IModel::parameters()` が返すテンソルの中身で、checkpoint(`*_best.pt` / `*_last.pt`)に保存されるのもこれ。

| 層 | 重みを持つか | 中身 |
|---|---|---|
| Conv2D | 持つ | カーネル(`C_out × C_in × k × k`)+ バイアス(`C_out`) |
| Linear | 持つ | 行列(`out × in`)+ バイアス(`out`) |
| BatchNorm | 持つ | スケール γ(`C`)+ シフト β(`C`)。ほかに running mean / var(`C` ずつ)を持つが、これは勾配で更新しない「バッファ」 |
| ReLU / Sigmoid / Softmax / Tanh | 持たない | |
| Pooling / IndexedPooling / Unpooling | 持たない | IndexedPooling が記録する indices は重みではなく、forward ごとに作られる中間値 |

## 2. 重みの数の式

```
Conv2D:    C_out × C_in × k × k  (+ C_out)   ← バイアス
Linear:    out × in              (+ out)
BatchNorm: 2 × C                              ← γ と β
```

**重みの数は入力画像の解像度に依存しない。** 同じカーネルを画像のすべての位置で使い回すため(重み共有)。
同じ理由で、**stride・padding・dilation・pooling も重みの数を変えない。**

例: 3×3 の Conv で 512 → 512 チャンネル
`512 × 512 × 3 × 3 = 2,359,296`(約 236 万、バイアスを除く)

## 3. 計算量(FLOPs)の式

```
MACs  = H_out × W_out × C_out × C_in × k × k
FLOPs ≈ 2 × MACs   (1 MAC = 掛け算 1 回 + 足し算 1 回)
```

重みの数の式に、出力の画素数 `H_out × W_out` を掛けたものになっている。
「重み 1 つを、出力のすべての位置で 1 回ずつ使う」と考えると覚えやすい。

| 3×3 Conv の例 | 計算 | FLOPs |
|---|---|---|
| 512→512、16×16(SegNet の最深部) | 16×16 × 512 × 512 × 9 × 2 | 約 1.2 G |
| 512→512、256×256(pooling なし) | 256×256 × 512 × 512 × 9 × 2 | 約 309 G |
| 64→64、256×256(pooling なし、チャンネル削減) | 256×256 × 64 × 64 × 9 × 2 | 約 4.8 G |

- 解像度を半分(縦横とも 1/2)にすると、計算量は 1/4 になる
- チャンネル数を 1/2 にすると、`C_in` と `C_out` の両方に効くので 1/4 になる
- **dilation は計算量を変えない**(参照する点の数は k×k のまま、間隔が広がるだけ)
- 学習 1 ステップは順伝播のおよそ 3 倍(逆伝播で「入力への勾配」と「重みへの勾配」の 2 つを計算するため)
- FLOPs(回数)と FLOPS(1 秒あたりの回数、ハードウェアの性能)は別物。実効 10 TFLOPS の GPU なら 309 GFLOPs は約 0.03 秒が目安(実際はメモリ転送で性能が出ないことが多い)

## 4. 学習時のメモリ

大きく 2 種類ある。

### 4-1. 重みに比例する分(解像度に依存しない)

float32(4 バイト)で、重みの数 × 4 バイトが 1 セット。学習中はこれが複数セット必要になる。

| 中身 | セット数 |
|---|---|
| 重みそのもの | 1 |
| 勾配 | 1 |
| Optimizer の状態 | Adam / AdamW は 2(1 次・2 次モーメント)、SGD(momentum あり)は 1 |

Adam なら **重みの数 × 4 バイト × 4 セット**。

### 4-2. 活性化に比例する分(解像度とバッチサイズに比例)

各層の出力は逆伝播のために学習中メモリに残る。

```
1 つの出力テンソル = バッチ × H × W × C × 4 バイト
```

256×256×512 なら 1 サンプルあたり約 128 MB。これが Conv・ReLU・BatchNorm の出力として層の数だけ残る。
**解像度を保ったまま深くすると、メモリを支配するのはこちら。**

## 5. このプロジェクトのモデルでの値

`TrainingApp.cpp` の `buildXxxGraph()` の構成から計算した(クラス数 3、3×3 Conv の重みのみ。バイアス・BatchNorm は合計数千個なので省略)。

### SegNet(`model_architecture = SegNet`)

| 段 | チャンネル | Conv 2 層の重みの数 |
|---|---|---|
| enc1 | 3 → 64 → 64 | 38,592 |
| enc2 | 64 → 128 → 128 | 221,184 |
| enc3 | 128 → 256 → 256 | 884,736 |
| enc4 | 256 → 512 → 512 | 3,538,944 |
| enc5 | 512 → 512 → 512 | 4,718,592 |
| dec5 | 512 → 512 → 512 | 4,718,592 |
| dec4 | 512 → 256 → 256 | 1,769,472 |
| dec3 | 256 → 128 → 128 | 442,368 |
| dec2 | 128 → 64 → 64 | 110,592 |
| dec1 | 64 → 3 → 3 | 1,809 |
| **合計** | | **約 1,644 万** |

- 重みだけで約 66 MB(float32)。Adam で学習すると、重み・勾配・モーメント 2 つで約 263 MB
- 重みの大半は enc4〜dec4 の 512 チャンネルの段にある。ただしこの段は解像度が 1/8〜1/16 なので、計算量は小さい

### SegNet の encoder 4・5 段目を dilated conv にした構成(`SegNetDilated`、解像度 1/8 まで)

- チャンネル構成は SegNet と同じなので、**重みの数も同じ(約 1,644 万)**。dilation と pooling の有無は重みの数を変えない
- 違うのは計算量とメモリ。SegNet では enc5・dec5 の Conv が 1/16 の解像度で動くが、この構成では 1/8 のまま動くため、その 2 段の計算量と活性化は SegNet の 4 倍になる(enc4・dec4 は SegNet でも 1/8 なので変わらない)

### 全層 dilation(pooling なし、入力と同じ解像度)の見積もり

| チャンネル | 重みの数 | 512→512 相当の層の計算量 | 学習時の活性化(256×256、バッチ 1) |
|---|---|---|---|
| SegNet と同じ(最大 512) | 約 1,644 万 | 約 309 GFLOPs / 層 | 数 GB〜 |
| 全層 64 チャンネル、Conv 20 層の場合 | 約 74 万(64×64×9 × 20) | 約 4.8 GFLOPs / 層 | 数百 MB 程度 |

pooling をなくすなら、チャンネル数を減らすのが普通。
小さい対象の検出で解像度を保ちたい場合は、重みの数ではなく**計算量と活性化のメモリ**が制約になる。

## 6. まとめ: 何が何を決めるか

| 変えるもの | 重みの数 | 計算量 | 活性化のメモリ |
|---|---|---|---|
| チャンネル数を 2 倍 | 4 倍 | 4 倍 | 2 倍 |
| カーネルを 3×3 → 5×5 | 約 2.8 倍 | 約 2.8 倍 | 変わらない |
| 解像度を縦横 2 倍(pooling を 1 段減らす) | 変わらない | 4 倍 | 4 倍 |
| dilation を上げる | 変わらない | 変わらない | 変わらない |
| バッチサイズを 2 倍 | 変わらない | 2 倍 | 2 倍 |
| 層を 1 つ足す | 足した層の分 | 足した層の分 | 足した層の分 |

dilation は重みも計算量も増やさずに受容野だけを広げられる。
全層 dilation の構成が重くなるのは、dilation のせいではなく、pooling をなくして解像度が下がらないため。
