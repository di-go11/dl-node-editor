# Rustを使用したAPI機能実装における要件定義

## 使用技術スタック

- Rust
- gRPC

## C++側(ai-engine)が現状要求している項目

C++側の学習処理は `ai-engine/.config`(キー=値形式のテキストファイル)を
`ConfigReader`([ai-engine/src/training/infrastructure/readConfig/ConfigReader.cpp](../../ai-engine/src/training/infrastructure/readConfig/ConfigReader.cpp))
で読み込み、`AppConfig` に変換して学習を開始している。
RustのAPIはまずこの項目をすべて満たせる形でgRPC経由で渡せる必要がある。

### 学習設定(AppConfig相当)

| キー | 型/形式 | 検証ルール | 備考 |
|---|---|---|---|
| `model_name` | 文字列 | 空不可(未指定時は既定値 "model") | チェックポイント名 `<model_name>_best.pt` 等に使用 |
| `model_architecture` | enum | `Sample` \| `SegNet` のみ | 層構成そのものはC++側にハードコードされている(下記「未解決のギャップ」参照) |
| `dataset_path` | 文字列(パス) | 空不可 | 学習用データセットのルートディレクトリ |
| `output_dir` | 文字列(パス) | 空不可 | チェックポイント保存先。既定値 `models` |
| `resume_from` | 文字列(パス) | 空許可(自動判定) | 空なら `output_dir` の `<model_name>_last.pt` があれば自動再開 |
| `save_last_every` | 整数 | 0以上 | 0 = 毎エポック保存 |
| `epoch_size` | 整数 | 1以上 | |
| `batch_size` | 整数 | 1以上 | |
| `input_width` / `input_height` | 整数 | 1以上 | 画像リサイズ先サイズ |
| `device` | 文字列 | `cpu` \| `cuda` \| `cuda:N` | `N`はGPU番号 |
| `Activefunction_type`(注: C++側実装のtypoで `activation` ではなくこの綴り) | enum | `ReLU` \| `Sigmoid` \| `Tanh` \| `Softmax` | モデル全体で1つだけ指定する、層ごとではないグローバル設定 |

### Optimizer設定(種別ごとに必要フィールドが異なる)

| optimizer_type | 必要フィールド | 検証ルール |
|---|---|---|
| `Adam` | `learning_rate`, `weight_decay`, `beta1`, `beta2`, `eps` | learning_rate: [0.0, 1.0] / weight_decay: 0以上 / beta1,beta2: [0.0, 1.0) / eps: 0より大 |
| `AdamW` | `learning_rate`, `weight_decay`, `beta1`, `beta2` | 同上 |
| `SGD` | `learning_rate`, `weight_decay`, `momentum`, `nesterov` | momentum: 0以上 / nesterov: bool |

未指定のフィールドは各Optimizerの既定値が使われる。選択中の`optimizer_type`と無関係なキーは無視される。

### モデル層構造(ModelGraph相当・現状は.configの対象外)

`ai-engine/src/training/entities/domain-objects/` 以下に定義されている層の種類とパラメータ。
GUIでブロックプログラミング的にモデルを組み立てる機能はこれに対応させる想定。

| 層種別 | パラメータ |
|---|---|
| Conv2D | in_channels, out_channels, kernel_size, stride, padding, dilation |
| Pooling | pooling_type(Max等), kernel_size, stride, padding |
| BatchNorm | num_features, eps, momentum |
| Linear | in_features, out_features, bias |
| Activation | activation_type(ReLU/Sigmoid/Softmax/Tanh), dim(Softmax時のみ) |
| IndexedPooling | kernel_size, stride, padding |
| Unpooling | kernel_size, stride, padding |

### 未解決のギャップ(要件定義で決める必要がある点)

- `.config`は学習全体の設定のみで、**層構成(ModelGraph)を外部から指定する経路が存在しない**。
  現状は`model_architecture`(`Sample`/`SegNet`)で選ぶC++側ハードコードの構成のみ。
  GUIでの自由なモデル構築を実現するには、ModelGraphをRust→gRPC→C++で渡す新しいAPIを設計する必要がある。
- 層のフィールド追加・並び順は`fingerprint`とチェックポイントの互換性に直結するため
  ([LayersParamsFields.hpp](../../ai-engine/src/training/entities/domain-objects/LayersParamsFields.hpp)参照)、
  Rust側のスキーマ設計時点から「既存フィールドの意味・順序は変更しない、追加は末尾のみ」という制約を踏襲する。
- 学習の進捗(epoch, best metric)を取得するAPIも`CheckpointMeta`相当としてまだ未定義。
